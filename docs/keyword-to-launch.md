# 从新词到上线：ChatGPT 调研与模板开发交接

标准路径：找到新词 → ChatGPT 联网确认搜索意图和资料 → 开发代理按调研结果使用本模板 → 可选前端改版 → 完成本站配置 → 验收并上线。

目标是每次只开发新词对应的内容、素材和必要玩法差异，复用登录、支付、积分、队列、退款、用户中心和后台。默认保留现有界面；用户选择改版时再改。适用范围优先为“一张照片 + 参考视频”的玩法；新模型、新输入或输出形式必须先验证适配，不能靠替换关键词承诺功能。

## 1. 交给 ChatGPT 的调研任务

只提供新词即可启动；已知的目标国家、语言、趋势原链接和竞品一并提供。没有地区信息时先研究英文海外市场，并把它标为假设。

可复制以下提示词，将方括号替换为实际内容：

```text
我要围绕新词「[新词]」做一个海外 AI 视频工具站，使用 ShrimpReel 模板。
目标市场：[已知地区/语言；未知则先研究英文市场]。
参考链接：[有则填写]。

请联网研究，并输出一份可直接交给开发代理的简报：
1. 这个词指什么；是否有同名或其他含义；趋势的起源、当前玩法及证据。
2. 实际搜索结果反映的主要意图：了解、观看、找教程，还是立即制作？
   给出代表性查询、结果页面/平台、观察日期、地区/语言及来源链接。
3. 最值得服务的人群与任务：用户提供什么，希望生成什么，最在意什么。
4. 首页应承接的主意图、主要操作、内容顺序、相关问题及长尾词。
   只有意图确实不同且内容有用时才建议独立页面，避免批量近义词页面。
5. 3–5 个有代表性的竞品/替代方法（不足就如实写），列出实际流程、
   可核实的价格/限制、用户仍未解决的问题；附链接和观察日期。
6. 玩法输入/输出、人物/衣服/背景/动作/音频/时长要求，区分必须与可选。
   判断是否适合“一张照片 + 参考视频”；模型能力待开发侧查官方接口及实测。
7. 素材清单、来源及授权状态；研究链接不等于可商用素材。
8. 按下方“开发简报”字段整理结论、来源和待核实项。

区分已证实事实、推断和未知。搜索量/难度没有可靠数据就标未知，
不要编造流量、用户评价、价格或模型能力；无法访问的页面要说明。
不要把社交热度直接等同于搜索需求，不把前排结果直接等同于排名机会。
```

### 开发简报（同一份交接内容）

无需重复撰写大份需求文档。调研结果按以下字段汇总，保留必要的证据链接；开发代理保存到本站 `.tmp/new-site/brief.md`（本地、不入库，换机器需一并交接）。

| 字段 | 要写清的内容 |
| --- | --- |
| 定位 | 新词、目标市场/语言、词义、主要搜索意图、用户要完成的任务 |
| 证据 | 查询与观察日期、来源链接、事实/推断/未知、竞品及差异 |
| 页面 | 首页主词与主要操作、内容顺序；必要子页面各自的独立意图及内链 |
| 玩法 | 输入、参考素材、输出、必须满足的效果、失败标准、待核实的模型能力 |
| 内容素材 | 中英文内容要点、示例图/视频、来源与授权、缺失项 |
| 站点身份 | 品牌、域名、客服及管理员邮箱；缺少时标待补，不编造真实值 |
| 界面选择 | 默认沿用；或用户指定的风格/参考站与需改动的页面 |
| 商业配置 | 期望时长、用户积分/售价、供应商成本依据；未知报价不编造 |
| 验收状态 | 模型是否实测、已获授权的预算/次数、外部账号缺项、上线授权范围 |

## 2. 交给开发代理的执行任务

将调研简报和可访问的模板仓库交给开发代理。使用包含 KIE 增量的模板版本：当前为本 fork 的 `codex/video-template-foundation` 分支；在主分支合入前，不要从未包含这些改动的上游 main 派生并假定已有 KIE。后续以合入功能的模板主分支为准。

```text
请依据附上的新词开发简报，用这个 ShrimpReel 模板建立独立站点。
先读 AGENTS.md、docs/keyword-to-launch.md、docs/fast-launch-kie.md 和
README 的部署说明。复用登录、支付、积分、队列、退款、用户中心和后台。

默认保留现有 UI；若我已指定改版，则按指定方向（默认 oil-ui）改前端。
先核对玩法与模型输入/输出、素材和运行环境，再开发页面。
把搜索意图落实到首页操作、页面内容、必要子页面和内链，不只换关键词。
每站独立仓库、资源、密钥与商品；不要复制旧站用户或配置。

按简报推进能完成的工作；非关键缺项记为 TODO(site) 并继续。
集中列出必须由我处理的账号/配置事项。付费模型测试遵守已明确的模型、
分辨率、预算与次数，不自行重复花费。已授权的步骤直接完成。
交付可查看的页面、验证结果、配置缺项及准确上线状态。
```

执行顺序：

1. **确认玩法可实现**：读取当前官方接口，确认输入、分辨率、大小限制、成本和任务状态。已有真实样例可复用其有效结论；需要付费实测时使用已授权预算与次数。模型达不到核心效果时先说明具体缺口，不先把页面写成已支持。
2. **初始化独立新站**：按 [快速启动](fast-launch-kie.md) 预览并执行 `site:new`；保留 Git 历史，将实际母模板仓库设为 `upstream`、本站仓库设为 `origin`。资源和凭据独立。
3. **落地页面与素材**：在 `site.ts` 和两份文案中设置品牌、时长、积分、定价、SEO、风格与参考视频。完成上传、登录、积分不足、处理中、成功下载和失败退款的可用路径，示例不能冒充真实成片。
4. **可选 UI 改造**：默认复用现有布局。用户要求改版即包含必要的页面、组件和样式修改授权，无须对每个文件重复确认；修改范围限于所选界面，保留现有业务接口和状态。默认使用可用的 oil-ui。记录本站改过的共享文件，后续同步模板时逐项审阅合并，不能用模板版本直接覆盖。
5. **完成配置并验收**：按下一节集中配置；运行改动相关检查和目标平台构建。有部署授权即继续发布与线上检查；没有时完成可发布版本并列明剩余动作。

## 3. “后台完成配置”的实际范围

网站管理后台在站点首次部署后才能通过公网访问。正确顺序是先配置云资源并发布到受限预发或维护状态，管理员完成设置和真实验收，再开放购买与生成。维护状态不算正式开业。

| 在哪里完成 | 配置内容 | 当前是否已有 |
| --- | --- | --- |
| 开发时由代理完成 | 品牌、文案、页面布局、参考视频、时长、用户积分、售价、SEO | 已有配置/代码入口；这些目前不在网站后台编辑 |
| 网站 `/admin/settings` | KIE 玩法、分辨率、每秒成本；公告、赠送积分、生成上限、维护与暂停收款；已配置的支付商切换 | 已有；后台有保存、审计和连接测试 |
| Cloudflare 后台/部署工具 | 域名、Worker、D1、R2、KV、Queues、环境变量、Secrets | 每站需创建/绑定；已有初始化与 doctor 工具，非一键全自动开通 |
| 外部服务商后台 | Google OAuth、模型 Key、支付商品与回调、发信域名及所用审核/人机验证服务 | 每站需配置；可用且已授权的连接器/脚本由代理完成，其余集中交给用户 |

详细字段见 [env.md](env.md)。后台连接测试中的发信测试会发送测试邮件，需在授权范围内执行；视频连接测试只查配置与余额，不生成。KIE 成本为 0 会阻止新生成；重新发布前需同步 `site.video.kie` 默认值供离线 doctor 核对。

## 4. 交付与上线标准

- **内容可用**：首页直接承接主意图，文案和素材真实对应当前能力，必要页面有独立用途；没有旧品牌、错误域名或阻止上线的 TODO。
- **本地完成**：相关类型/单元/浏览器检查通过，目标平台构建通过，并提供可查看的页面或截图。界面未变化时复用有效检查，不重复全量回归。
- **配置完成**：独立资源和域名已绑定、迁移已应用、参考素材已上传；doctor 无阻断问题，正式支付的商品、密钥与环境一致。生产迁移遵守实际审核授权要求。
- **真实流程验收**：本站 Google 登录、支付到账、积分扣除、真实生成、R2 转存和下载有证据；失败退款用受控测试验证。费用、真实支付和发信按已有授权执行，未验收项必须明示。
- **正式上线**：部署版本与提交可追溯，维护/暂停开关按实际营业状态设置；验证公开页、canonical、robots、sitemap 和内链。可抓取与已被搜索引擎收录分别报告。

最终只汇报四件事：完成了什么、页面/版本链接、实际验证到哪一层、还有哪些必须处理的缺项。资料研究、UI 改造和配置都服务于这一次具体新词，不为尚未出现的玩法扩建通用平台。

## 与仓库原有 Skill 的衔接

保留 `.claude/skills/new-hot-site/` 原文，使用它的内容和素材操作建议；涉及当前新词流程时以本项目本文及用户当次要求为准。原 Skill 中“脚手架保留本地 vars”“主色修改逐次确认”“无论授权都只列资源清单”等旧流程不适用于这里：当前脚手架生成生产配置占位，本地开发由 `vite.config.ts` 覆盖为 mock；明确授权的 UI、配置或部署工作直接执行。不得把模板文件存在当成真实服务已验收。
